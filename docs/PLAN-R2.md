# DomainHunter · R2 规划（功能定义 → 竞品对照 → 设计 → 实现）

## 0. 运作方式（老板指令）
- 本会话为项目负责人：规划、派活（子会话）、监督、测试驱动走查。
- 测试驱动：每轮上线后由 QA/UX 走查线上真实环境，问题清单驱动下一轮。

## 1. 技术选型（最流行 + 最适合）
- 前端：React 18 + Vite + **Tailwind CSS + shadcn/ui** + **lucide-react** 图标；设计规范贴 shadcn 设计语言（Radix 无障碍底座），响应式移动端优先
- 后端：**Cloudflare Workers + Hono**（边缘、零运维、流式响应天然适配）；数据 D1（收藏/搜索历史）、KV（限流/缓存）
- AI：DeepSeek（生成/反思），保留可替换接口

## 2. 我们的功能（先自己想）
P0（本轮）
1. Agent 检索主流程升级：需求理解确认（AI 复述理解+可编辑）→ 分轮构思展示 → 实时核验 → 打分排序（长度/读感/寓意贴合/品牌感）→ 可注册清单
2. 结果卡片：域名 + 寓意 + 评分 + 注册商跳转（阿里云/腾讯云/Namecheap/Cloudflare）+ 复制
3. 收藏（本地）+ 导出 CSV/TXT
4. .cn 等无 RDAP TLD 的 WHOIS 回退（服务端）
5. 视觉全面升级为 shadcn/ui 设计语言，移动端适配

P1
6. 收藏云同步 + 掉落监控提醒；7. 批量模式（高级）合并进「专业版」页；8. 多语言；9. 免费额度/付费

## 3. 竞品设计要素对照
| 竞品 | 值得借鉴 | 我们的取舍 |
|---|---|---|
| instantdomainsearch | 即时反馈、四态徽章过滤、注册商下拉、bulk 工具矩阵 | 徽章过滤 + 注册商跳转采用 |
| DotFind.ai | 「AI 生成 + 仅显示可注册 + 三维评分」卡片流、收藏/邮件提醒 | 评分卡片采用；提醒放 P1 |
| kaido（开源） | 卡片 checking 态原位更新、<3 个可用自动重试、5 轮上限+询问继续 | 已实现循环；卡片原位更新采用 |
| vacant（开源） | RDAP→DNS→WHOIS 级联、价格预估、只显示可注册开关 | 级联采用（补 WHOIS）；价格 P1 |
| namelix | 风格筛选（短/品牌感/关键词）、保存偏好学习 | 风格筛选采用（下拉：极客/商务/文艺/拼音） |

## 4. 本轮派工
- ui-designer 子会话：输出 UI 原型设计稿（HTML 原型 + 截图），覆盖：首页检索、Agent 进行中、结果列表、移动端
- qa-engineer 子会话：线上 hunt.zalize.com 全面走查（功能/体验/边界/移动端），输出 P0/P1 问题清单
- 负责人（本会话）：验收设计稿 → 按稿实现（shadcn/ui 重构）→ WHOIS 回退 + 打分 → 部署 → QA 回归

## 5. 验收标准
- UI 达到或超过 DotFind/instantdomainsearch 的现代感；移动端无横向滚动、可单手操作
- 一次典型检索（中文描述）≤60s 给出 ≥10 个可注册且评分排序的结果；.cn 状态不再大量「未知」
